# W4 Decision: LVR Latent Step Localization

Date: 2026-05-24

## Decision

Week 4 extends the W3 true LVR hidden-feedback intervention from a single last-step patch into per-step localization. The same metric id, `lvr_latent_patch_answer_transfer`, remains the entry point so W3 artifacts stay comparable. W4 is activated by `lvr_latent_patch.patch_steps: ["each"]`.

## Implementation Contract

- Source generation captures real `output_last_position_hidden_state` tensors during LVR mode.
- Target generation is run once clean, then once per captured source latent step.
- Each patch injects exactly one source state at the matching `forward_pre.last_position_hidden_state` step.
- Sample records include `step_results[]`; reductions include `best_step_transfer_rate`, `best_step_index`, `step_transfer_auc`, `last_step_transfer_rate`, and `n_steps_evaluated`.
- W3 `latent_answer_transfer_rate` remains the last-step transfer rate for backward compatibility.

## Gate

Official config: `config.lvr_latent_patch.stepsweep.yaml`

Acceptance command:

```bash
bash tools/run_and_hold.sh 0,1,2,3 ./venv/bin/python run_all.py \
  --config config.lvr_latent_patch.stepsweep.yaml \
  --models lvr_7b \
  --only lvr_latent_patch_answer_transfer \
  --device cuda:0 \
  --run-name w4_lvr_latent_stepsweep_n50_s8

./venv/bin/python tools/validate_w4_stepsweep.py \
  runs/w4_lvr_latent_stepsweep_n50_s8 \
  --min-pairs 50 \
  --min-steps 2
```

## Scope

W4 localizes across latent feedback steps at `lvr_steps=8`. Layer-level latent intervention is deferred until step-level signal is inspected.
